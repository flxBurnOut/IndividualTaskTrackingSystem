# 固定 Codex 项目与原文件目录

软件从 0.9.1 起，把内部讨论、业务记忆和原文件各自放在明确的位置。

- Codex：0.11.2 起，在设置中首次启用并保存 Codex 协助，会准备当前数据空间下的 `Codex事务助手`，通过 Codex 桌面自身入口创建正式项目并打开空白对话，再核验项目与 MCP 连接。同一数据空间复用同一项目。软件内部讨论明确绑定项目；普通对话从该项目中新建。
- 数据库：任务、日计划、完成反馈、个人记忆、来源关系及文件索引保存在 `database.sqlite3`，读取这些记录不需要重新解析课件或工作簿。
- 原文件：`原文件/Y2S1` 保留迁入时的相对目录、文件名和原始字节。课程或项目首页的“打开文件夹”直接进入所属目录。新上传资料也保存到对应目录。
- 内部版本：`blobs` 保留去重后的不可变内容，供提取、校验、备份和重建使用。可浏览原件是独立副本，不是指向内部存储的可写硬链接。

## 日常使用

查看课件，在课程首页点“打开文件夹”，然后用常用阅读器打开文件；单个资料的“打开原文件”也会使用这个目录。设置的数据页提供“打开原文件目录”。

保存新课件、通知、邮件、截图，继续使用课程中的“添加资料或通知”。原件目录和数据库资料记录会一起建立。同名且内容不同的文件另存新版本，不覆盖旧件。

原件默认只读，用于保留导入时的内容。如果另存或修改了文件，需要重新导入才能成为软件的新资料；软件不会据此自动改写旧记忆、任务或完成反馈。旧 Y2S1 工作簿仍是迁移时的原件，当前事务状态以软件数据库为准。

原件目录的文件被移动或删除，可再次打开该资料或准备所属文件夹，重新从内部版本还原。已修改的文件会保留并提示核对，不会被自动覆盖。

## 迁移与备份

复制完整数据空间会保留数据库、原件目录与内部版本。使用软件备份时，保存数据库和已登记的不可变版本，避免把同一份内容重复备份两遍；恢复后的原件目录可按数据库中的相对路径重建。仅在文件夹中新增但未导入软件的文件，不属于软件备份的已登记资料。

固定项目路径不依赖发布版本目录。升级软件后会继续使用同一位置；移动或恢复数据空间时，旧连接会基于软件保存的讨论记录和当前业务事实在新位置重建。旧临时项目的历史会话保留，新的内部讨论不再使用随机临时目录。

## 实现依据与验证

会话创建、继续和命名使用 [OpenAI 官方 App Server 接口](https://learn.chatgpt.com/docs/app-server)。集成验证应使用虚构消息，并分别检查会话的项目归属和续接行为。

文件复制采用分块读取、内容哈希核验、原子发布和有界批次；界面不会把完整原件加载进内存。文件夹位置和校验时间作为可重建索引保存，普通浏览不会把任务和记忆写回旧工作簿。

安装和文件完整性验证应在隔离数据空间进行，记录留在本机。


## 普通对话处理群消息、邮件和突发事件

在个人事务管理的“设置 → Codex 协助”启用并点击“保存并连接 Codex 项目”。软件会自动完成工作区文件、项目级 MCP、专用目录的 Codex 信任配置、桌面项目创建与业务接口验证。已有明确“不信任”选择不会被覆盖。需要本机已安装并登录 Codex；这一步打开空白对话，不自动发送消息。

随后从 Codex 侧边栏的“Codex事务助手”中新建普通任务。可以粘贴群消息、邮件正文或附带截图/文件，直接说明希望记录、更新或安排什么。每轮先读取最新数据库记录，写入通过带版本与回执的 MCP 业务命令。不同任务共享已保存的业务数据，不要求同一段旧会话，也不自动镜像聊天全文。

只使用 Codex 时，MCP 会按需启动独立业务服务。只使用软件界面时，同样直接操作该服务；关闭软件中的“后台协助”开关不会删除项目或阻断普通 Codex 对话的接口。

软件生成的“个人事务 · 每日计划”等后台会话仍受候选 JSON 和工具隔离约束。新突发事件使用普通任务，不在这些后台会话里自由聊天。

软件升级或数据目录迁移后，再次保存 Codex 设置可修复受管理连接。已有其他 MCP 和个人配置保留；受管理区域被修改时明确报错。首次配置和日常维护均通过软件设置完成。

实现边界：通过注册的 `codex://new?path=...` 协议进入桌面正常创建流程，随后由 app-server 的 project/list 和 project/read 核验；不直接修改桌面的私有项目数据库。项目接口仍随 Codex 版本演进，不支持的运行版本会返回“连接尚未完成”，不会仅凭文件夹创建就报告成功。
