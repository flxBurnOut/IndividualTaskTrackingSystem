## 状态与验证口径

- **实现**：该行明确列出的核心确定性机制已存在，有针对性测试；右列仍列出不包含的外部能力。
- **部分**：只有记录、部分算法或基础接口；未实现的历史行为明确列在右列。实体可创建、字段可填写、模块可配置，均不等于已经具备相应专门业务算法。
- **配置后需验**：用于附加标记。代码存在，但实际使用还依赖该机器的配置、权限、登录、持续运行或客户端接入；不把配置存在当作实际投递或执行证明。
- **延期旧迁移**：本轮明确不读取、导入或切换旧资料。不能把暂不迁移扩展成软件本身缺失功能的理由。

## 本轮交付前需要优先决定的机制

1. **规划语义**：祖先/类型作用域及周期警戒已接通。学期日历、低状态结构的配置约束、已执行块保护、有效策略驱动的自动局部重排、关联准备任务的考后窗口关闭仍需继续实现。
2. **层级可用性**：已补项目 → 阶段 → 任务 / 里程碑，并用 E 验证移动后项目子树统计。目标是跨领域关联，非强制主父级；这一设计不应误记成缺口。后续扩展仍需明确归属、依赖和证据关系，不混成一棵树。
3. **每日复核覆盖**：无日计划时已补明确 dated 任务 / 当日事件作为回退对象；需验证当日选择范围，不能把所有活动任务都问成今日安排。23:00 与 08:00 是不同 schedule，分别去重，不把“问了没有答”写成事实；本软件内通知与 Codex 聊天投递必须分别说明。
4. **储存可持续性**：当前流式导入、内容去重、限额、低空间保护和备份私有内容池降低重复占用；唯一来源、成果、失败候选和备份不会自动清理。**因此现版本不具备长期自动回收保证**，应补备份保留和可重建缓存策略后再作长期存储承诺。
5. **执行器边界**：SSH、Conda/Jupyter 修复、Notebook 执行、外部发送/报名/上传、Blender、文档渲染质检尚未实现。它们需要受控执行器与独立结果/回执验证，不能由通用 run / external_record 实体替代。

## 性能与稳定性的实际证据边界

既有合成短测直接插入 10,000 个任务、1,000 个事件、100,000 条历史作为 fixture；这不是 111,000 次真实业务写入性能测试。此前短测的 100 次循环无失败，三次查询组合中位数约 94 ms、P95 约 97.5 ms；100 次反馈提交中位数约 10.4 ms、P95 约 11.1 ms。单个 Core 测试进程私有内存由约 14.4 MiB 到 18.9 MiB，并启用了 tracemalloc；这不是 GUI + 常驻服务 + 模型/文档子进程的总内存结论，也不能用起止两点证明不存在泄漏。

`tests/test_scale.py --soak-seconds 1800 --report <报告路径>` 已完成一次 1800.011 秒的核心合成观测，15,075 轮无失败；三查询组合 P95 为 159.288 ms，100 次反馈提交 P95 为 11.616 ms。此观测在实施期间启动，不能替代最终全部业务/界面/模型的整机长稳验证；8 小时未运行。详细范围以实施验收记录为准。

本表共列 49 个历史类别，没有用未迁移的真实资料检验个案质量。所有“配置后需验”都需要在目标机器上进一步核对，尤其 MCP 同目录接入、模型权限、定时服务持续运行和产物字体；旧资料的内容质量、真实外部回执、全历史绝对完整性不在本轮合成验收结论之内。
