# v1.0.1 发布说明

修复已有计划通过 MCP 无法修改、修改或追加计划可能绕过前置依赖，以及受管讨论读取不到依赖的问题。继续使用原数据空间，保留计划修订历史与实际完成记录。

## 本次修复

- 通用 MCP 命令根据完整的内部能力检查执行权限，不再因能力目录超过响应长度而误报“未注册”。对外能力查询按预算提供索引和详情；未知命令与受管会话的直接写入仍被拒绝。
- 修改或追加计划时，尚未执行的旧条目也重新核对前置任务及顺序。保留条目内容不会豁免依赖；已反馈、过去日期和当天已结束的历史条目仍须原样保留。
- 受管每日计划会话区分首次新建与修改现有计划。修改携带原计划编号和版本；期间计划发生变化会要求重新核对。候选须在软件确认后才保存，不形成两套并行的当前计划。
- 上下文中的任务与可安排事项提供依赖读取入口，按页返回前置、后置及所选日期的完成证据。计划引用的前置依赖须完整读取；依赖或相关完成状态变化后须重新核对。排进计划不代表实际完成。

本次不提供新的任务拆分窗口、跨日条件排程器或时间轴排序功能。原始请求中的先后偏好仍须与已登记的硬性前置关系区分。

## 下载与使用

从 [v1.0.1 Release](https://github.com/flxBurnOut/IndividualTaskTrackingSystem/releases/tag/v1.0.1) 下载 `PersonalManagement-1.0.1-Setup-x64.exe` 和 `SHA256SUMS.txt`。仓库保持私有，下载需要访问权限。本安装包未签名。

安装器按当前 Windows 用户安装，默认程序位置为 `%LOCALAPPDATA%\Programs\PersonalManagement`，默认数据位置为 `%LOCALAPPDATA%\PersonalManagement\data`。已有用户通过“为已有数据创建快捷方式”选择原目录；普通卸载保留业务数据。程序或后台服务占用安装目录时，安装器会停止并提示处理。

此修复涉及业务服务和 MCP 进程，两者都需使用新版程序。安装完成不等于正在运行的旧 MCP 进程已经更新；应在空闲时重新加载对应连接，并核对实际使用的版本。无需重新导入数据，也不自动重发此前失败的修改请求。

完整用法见[使用说明](https://github.com/flxBurnOut/IndividualTaskTrackingSystem/blob/v1.0.1/docs/使用说明.md)，业务接口及候选边界见[Codex 接口](https://github.com/flxBurnOut/IndividualTaskTrackingSystem/blob/v1.0.1/docs/Codex接口与后台推理.md)。
