# 开发与扩展

适用于个人事务管理 v1.0.1。本次修复计划修改入口、既有条目的依赖校验和依赖上下文读取；任务拆分与跨日条件排程不在本次范围内。

## 开发环境与运行

需要 Python 3.12 或更高版本。依赖和可选开发工具以 `pyproject.toml` 为准。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m management --data-dir .local-data
```

`--service` 只启动业务服务，`--mcp` 提供 MCP 接口，`--choose-data` 只为本次启动选择数据空间。`--install-shortcuts --choose-data` 创建长期绑定所选数据目录的快捷方式；不会移动或导入原数据。开发和验收必须使用独立的合成数据目录，不把日常业务库作为测试夹具。

## 主要模块

| 领域 | 模块 |
| --- | --- |
| 类型、事实、事务和回执 | `schemas`、`storage`、`core` |
| 计划、执行反馈与统计 | `planning`、`daily_flow`、`reviews`、`domains` |
| 课表、发生次和准备任务 | `timetable`、`occurrences`、`recurring` |
| 补欠与任务状态 | `catchup`、`task_views`、`tasks_delete` |
| 资料和内容存储 | `sources`、`resources`、`library` |
| 分批材料与上下文 | `material_worker`、`materials`、`context_*` |
| 会话与候选协调 | `conversations`、`session_coordinator`、`conversation_progress` |
| 正常桌面连接 | `codex_installation`、`codex_ipc`、`desktop_*`、`native_desktop` |
| 服务和 MCP 适配 | `service`、`client`、`runtime`、`mcp_server`、`mcp_routing` |
| 界面 | `gui*`，只调用业务服务 |

本机服务独占业务写入，GUI、MCP、定时器和扩展命令都走 Core。SQLite 使用 WAL 和完整同步策略；列表与历史分页，模型没有直接数据库或任意 SQL 接口。

## 命令与状态语义

业务命令使用稳定 `request_id`、当前 `epoch/revision` 和必要实体版本。同编号同内容恢复原回执，同编号不同内容拒绝。不同请求编号不天然语义去重；复盘、托管资料、准备发生次等专用操作按各自规则去重。

长文件操作先登记意图，在业务事务外进行耗时 I/O，再结算结果与回执。未知结果应查询原操作；不得直接用新编号重放。恢复数据空间后更换数据身份，使旧上下文和候选失效。

进度与上下文读取缓存不是用户业务事实。它们记录材料定位、版本、检查点、处理代次和回执关联，不能把“已提取”“已交给模型”“已分析”“已采用”压成一个完成标志。

受管候选在一次业务事务中采用全部封存动作；失败整体回滚。直接 MCP 多命令是多个事务。现有计划修改走保护历史的专用入口，不能用新建计划绕过已有反馈。

## 扩展方式

1. **字段和视图**：声明式模块增加类型字段，字段版本受保护；停用后历史数据保留。
2. **规则**：支持声明式字段校验，以及有范围、效期的容量、保护时段和提前警戒。
3. **工作流**：调用已有受控操作并提供默认输入，使用正常类型化表单，不执行模块 JSON 内的任意代码。
4. **类型与算法**：新增命名空间类型，或注册 `CommandDefinition`、`QueryDefinition`，提供稳定名称、版本与自包含 schema。

算法注册来自受信应用代码。命令处理器参与同一事务，不在事务内运行模型或慢 I/O；有耗时任务时先登记持久作业，由受控执行器处理。新增复杂界面或外部能力仍需实现与验证，不是导入 JSON 就具备任意功能。

`capabilities` 返回当前类型、字段、流程和已注册扩展。MCP 按实时白名单调用。新类型可进入现有菜单和表单，但不会自动成为新的一级导航。

## 业务扩展边界

### 每日计划和复盘

`daily_tasks` 是日期相关待办投影；`add_to_plan` 需提供已读计划快照，追加任务时保留旧块，不自动改变休息模式。`revise_plan` 保留已反馈或过去条目。

`create_plan` 一次保存一个日期，最多100个块，检查时段、容量、任务完成条件和依赖。核心分钟数为整数。没有专门的多日区间事务 API；普通对话可逐日协调，一般候选可包含多个合法动作，但不能因此跳过逐日证据读取。

复盘的完成、出勤、提交、掌握和实际用时分别记录。固定课程按实际发生次反馈；只有明确缺课需补才建立补课关联，不能从未知出勤推断欠课。

### 准备和补欠

`recurring_rules` 与 `preview_recurring` 只读；`set_recurring_rule` 修改规则，`materialize_recurring` 显式生成有界日期窗口。规则和发生次账本防重复；修改节点与规则不覆盖已有任务和反馈。后台保存成功处理位置，有限追补遗漏日期，超范围需明确核对。

补欠复用任务与反馈，不建第二套进度事实。累计数量与完成确认独立，未知不转为0，降低数量需引用原记录并说明。已有完成条件不能在登记补欠时降低；范围或单位改变不能套用不相容的旧数量。

### 课表

课表容器保存名称与日期规则；实际系列使用共享日程实体。`timetable_week`、每日固定安排、警戒与准备生成共用日期和教学周判断。

`apply_timetable` 在事务内校验容器及实际行版本；未包含的旧行不自动删除。Recess 周必须有明确日期，旧规则保持原含义，不从空白周猜校历。

GUI 支持原系列同星期日期的单次停课或改时间；没有完整的单次跨星期迁移编辑器。周视图也暂不提供独立 Recess 周标题。新增此类界面不能只改变视觉而绕过共享日程语义。

## 长资料与候选

新增集合用 `context_service.register_collection` 注册，SQL 条件必须参数化并来自受信代码。记录细节通过有界读取器取得，索引和第一页不代表全量覆盖。

解析器按自然单元输出稳定位置、文本、图片或缺口，`parse_batch` 按预算保存继续位置。原件和提取块按内容哈希复用；改变解析语义应更新提取器版本，避免把旧缓存当作新结果。

当前机制没有旧的整份8页上限。长文档分批处理，但每批仍有资源预算，格式不支持或无法恢复的错误必须作为缺口返回。压缩与检查点接续沿原作业，不通过重置配额假造完成。

单批候选动作有界，累计候选用清单和分页读取。采用时校验整个清单。结束后的可重建缓存可以清理，事实、来源、回执和必要修订记录保留；清理缓存不承诺 SQLite 文件立即变小。

内置课程笔记流程通过有限技能注册表加载。本轮用户请求才选择技能，资料正文不能激活任意技能或路径。高级文档成果生成与采纳保留业务接口和执行器，但没有覆盖全部流程的独立 GUI，应在接入说明中明确。

## 桌面连接维护

正常桌面共享使用版本相关私有 IPC；必须验证服务器进程、路径和包身份，并以自己的客户端身份连接。不改 Codex 内部数据库，不伪造代理工具调用身份，不以隐藏模型替代共享模式。

发送意图先落盘，响应与历史按精确会话、回合和代次核对。断连后重新订阅，不能重发未知请求。正式取消与服务脱离不同；新代次进度只能由当前任务身份建立，旧回调不得回写。

官方 App Server 的配置、空会话创建和只读历史接口与私有桌面路由职责分开。接口 schema 中存在字段不代表当前运行时一定支持；适配应有协议、身份、重复、丢页、未知结果和恢复测试。

GUI 对象在所属线程释放，异步回调核对窗口生命周期、数据身份及请求代次；不得用后台线程直接更新或销毁 Qt 控件。

## 构建和发布检查

```powershell
.\.venv\Scripts\python.exe -m pytest -q --basetemp .test-output/pytest
.\.venv\Scripts\python.exe packaging/build.py
.\.venv\Scripts\python.exe packaging/smoke.py
.\.venv\Scripts\python.exe packaging/build_installer.py --bootstrap-compiler --check
.\.venv\Scripts\python.exe packaging/build_installer.py
```

便携构建输出 `release/PersonalManagement-1.0.1/`。用户安装器为 `PersonalManagement-1.0.1-Setup-x64.exe`，使用 Inno Setup 按用户安装；最终发布同时提供 `SHA256SUMS.txt`。首次执行 `--bootstrap-compiler` 会从官方来源下载固定版本的编译器，核对哈希和签名后仅解包到 `.build/tools`；`--check` 校验输入并编译脚本，但不生成安装包。

应用构建会根据实际打包依赖生成 `THIRD_PARTY_NOTICES.md` 和许可证目录，并补充固定版本的官方 Qt 许可与来源说明。下载缓存位于 `.build`；缺失许可、版本不符或哈希异常时构建停止。安装器输入还会检查三个程序的版本、私有数据文件和前后哈希。

默认程序目录与数据目录分离。安装器遇到程序占用应提示处理，不强杀进程；普通卸载保留数据。当前没有代码签名证书，应在发布说明中如实标注，不能把校验和等同签名。

发布检查分开记录源码测试、冻结包检查、真实业务回传、GUI 日常体验和长期稳定性。用户完成日常体验验收不等于所有人工清单自动通过，也不以单元测试替代模型及安装行为验证。

分发范围只含通用代码、模板、图标、声明式依赖和文档。个人数据、会话、账号、实际配置、迁移备份、安装日志与本机验收材料不进入提交或安装包。忽略规则只管收集范围，历史隐私检查仍需单独处理。

测试、演示和发布烟雾检查使用独立合成记录；失败时保留原请求和回执，不为取得绿色结果重复真实业务操作。
