# 开发与扩展

Python 3.12 + PySide6 Qt Widgets；本机 HTTP 服务独占业务写入，SQLite WAL/FULL，MCP stdio 作为薄适配器。后台 Codex app-server 只返回候选。GUI、MCP、定时器、扩展算法的提交都走 Core 的版本校验、事务与回执。

## 本地开发

在项目的 `.venv` 中安装 `pyproject.toml` 所列依赖。使用 `.venv/Scripts/python.exe -m management --data-dir <独立测试目录>` 运行；`--service` 只开后台，`--mcp` 只提供 Codex 接口。测试：`python -m pytest -q --basetemp <新的测试目录>`。发布：`python packaging/build.py`；发布实测：`python packaging/smoke.py`。

源码职责：`storage/core/schemas` 负责事实和事务；`planning/domains` 负责确定性规则和统计；`resources/document_worker` 负责有界成果处理；`sources/source_worker` 负责资料托管与提取；`conversations` 保存范围会话及候选生命周期；`scheduler` 管理持久作业与发生次；`service/client/runtime` 管理共享服务；`mcp_server/ai` 隔离模型和协议；`gui*` 只调用服务。

## 四种扩展

1. **字段/视图**：安装声明式模块，增加指定类型的字段。字段版本受保护，停用后原数据保留。
2. **规则**：模块可声明 required/min/max/one_of 校验；规划规则另支持主归属范围、类型筛选、效期、容量、保护时段、天数及日历月提前量。
3. **工作流**：声明式工作流调用已有受控操作并提供缺省输入，界面使用正常类型化表单。没有 eval，也不运行模块 JSON 中的代码。
4. **类型/算法**：模块可增加命名空间内的新实体类型与父类型。新算法使用 `extensions.CommandDefinition` / `QueryDefinition` 注册，提供稳定名称、版本和自包含 JSON schema。处理器接收 Core/connection/payload（命令另有 request_id），参与同一事务。新增复杂 UI 或外部执行器仍需写代码并配测试，不是任意新功能零开发。

注册算法是受信任应用代码，在服务启动时注册；用户导入 JSON 不能偷偷导入 Python 模块。扩展命令不得在事务内运行模型或慢 I/O；需要成果时先登记 durable job，再由受控执行器处理。

`capabilities` 提供当前类型、流程、命令和代码扩展。MCP 通用入口按实时能力白名单校验；新类型自动出现在已有导航的类型菜单和表单中，不能自动增加一级导航。复杂新算法需配对应的可读 UI 动作，不能只留下一个隐藏 API。

## 持久化与失效

request_id 相同且参数相同可恢复同一回执；参数变化拒绝复用。通用命令不保证不同request_id语义去重；每日复盘、相同资料收存和课程来源候选等专用命令实现其业务范围内的去重。全局 revision 用于保守并发校验，实体 version 用于编辑；恢复 epoch 变化使旧入口失效。每次业务轮次重新读上下文，旧聊天文字不会自动更新。

文件操作先登记 io_operations。长文件 I/O 不占业务锁，完成后保存结果和回执；中断中的操作需要核对，不盲重放。未知 schema 在修改数据库前拒绝。代码扩展必须保持这些边界。

## 资源及测试边界

列表和历史分页；作业列表只取摘要，单项按需加载完整候选。AI 输入有界，必要约束不能静默截断。文档执行器单进程树 1 GiB / 120 秒，输出仅在登记工作区；临时文件和唯一成果的生命周期不同，不能靠目录名自动删除。

测试库与正式空空间分开。发布通过白名单收集运行代码与依赖，不带 `.analysis`、测试库、账号配置和 runtime.json。本机的历史检查报告不随源码分发；单元测试不代表真实模型、安装包或长时间稳定性已经验收。

## 0.3 新增边界

资料读取在独立子进程运行，45秒/768MiB上限；原件最多128MiB，正文最多10万字符，PDF/Office最多80文本单元，扫描页最多8张。解析结果文件64KiB、coverage16KiB、警告条数和长度有界。超限/异常不阻止原件登记。来源快照、正文和图片都用已有内容地址blob机制保存，备份收集全部派生指纹。

讨论每轮最多12份选定资料、8张图、28000字符资料正文；必要输入超限明确要求分批。source_ids省略沿用，明确[]清空，明确列表替换。公共create_job不能注入内部会话编号/历史/本地图片路径。新解析格式应在source_worker扩展受控读取器；新scope需统一规范化与稳定键，避免用UI最近一次作业代替上下文。


## 0.4 任务与周期规则接口

`daily_tasks(date,limit,offset)` 为只读分页候选视图，返回最新计划快照。`add_to_plan(date,target_id,plan_id,plan_version)` 必须传入该快照，无计划显式传null；它追加无具体时间的任务并保存新计划版本，保留旧块与已有反馈，不自动更改休整模式。

`recurring_rules(anchor_id?,scope_id?,limit,offset)` 与 `preview_recurring(rule_id?,start?,end?)` 不写入。`set_recurring_rule` 创建或按id/version编辑规则；`materialize_recurring` 明确生成指定窗口的任务。字段见能力中的recurring_rule及实现：anchor_id、title、content、completion_gate、days_before、estimated_minutes、enabled、effective_from/until、source_text。生成窗口最多31天、500项；周期日期直接跳转到窗口，不逐日扫描全部历史。稳定rule+occurrence ledger防重，规则变更保留旧任务，事件系列改动要求显式确认重新绑定。

GUI、外部MCP、后台轮询共用这些接口。AI只能提出set_recurring_rule候选，用户确认后执行；不允许候选自行生成任意脚本或直接写库。新anchor必须先保存，后续轮次使用真实ID绑定。恢复备份保留ledger与技术进度并暂停规则。后台逐规则保存成功处理日期；跨日重启最多追补31天，真实更早缺口提示核对。新建或明确修改规则从当前日开始，停止期间不自动回填。单规则错误隔离为可见通知，健康恢复会清除告警去重标记，以便复发再次提醒。

`codex_models(executable?)` 在数据库事务外调用本机app-server model/list；不启动thread/turn，不读取配额，不写用户配置。模型列表有分页、数量、超时上限，界面以返回model标识保存选择。


## 0.5 外观、课程编辑、补欠与笔记技能

外观持久设置为settings.appearance：theme（light/dark）、font_family、font_size（11–20px）、workspace_sidebar_collapsed。服务端仅校验配置；字体发现和可移植回退由Qt客户端完成。统一gui_theme调色板覆盖主窗、对话、月历、图表和聊天；读取/保存有快照保护，不覆盖未保存选择。

补欠复用task及feedback，没有第二套进度数据库。recovery_summary(course_id?或task_id?,as_of?,limit,offset)读取完整汇总和分页任务；set_recovery_task登记/修正定义，可引用original_task_id保留原任务；record_recovery_progress追加累计量和独立完成确认。已有完成门不被降低，未知不写0；减少累计量引用最新feedback并说明原因，总量更正保留前后值与来源。不同量纲分别汇总。普通create/update不能绕过catchup元数据校验，实际反馈与每日计划仍走原事务/幂等/版本流程。

course-notes以独立SKILL.md保存在src/management/builtin_skills/course-notes，并作为数据资源进入发布包；外部Codex安装同一份技能。skill_workflows维护有限注册表，send_message支持显式skill_id或从用户当前请求匹配，自然语言“这是课件，整理笔记”可触发。来源材料不能激活技能，任意路径和未注册技能会被拒绝。只有本轮selected_skill指令进入当前模型上下文，旧讨论不会使技能永久生效。skills查询返回可用技能和版本指纹。

笔记仍通过已有候选确认保存为当前课程的note；正文在讨论中展示，课程首页用摘要卡。所有日程、考核、节点、任务和笔记的编辑都经统一update及版本校验；界面不直接改数据库。


### Qt界面生命周期

Qt要求对象在所属线程释放。Python循环垃圾回收可能在执行分配的HTTP工作线程触发，因此GUI进程在启动ServiceBridge前安装一次主线程回收控制器：保留引用计数，由QTimer按原阈值进行代际回收，并定期完整回收。业务服务和解析子进程不导入该策略。退出时保留已经接受的请求与回执，等待全部已登记桥接线程停止后才恢复原GC启用状态和阈值；不会强行终止写入线程。

主题回调使用弱引用，不长期持有关闭的窗口。外部库显式在工作线程调用gc.collect不属于本程序自动回收策略的保证范围。依据：[Qt QObject线程与删除规则](https://doc.qt.io/qt-6/qobject.html)、[Qt线程与对象说明](https://doc.qt.io/qt-6/threads-qobject.html)。


## 0.6 每周课表接口

`timetable` 是顶层课表资料容器，允许仅有名称与未配置学期依据；不会创建日程。`timetables(id?)` 返回容器及从实际 event 推导的 rows；列表分页最多100项。`timetable_week(week_start,timetable_id?)` 是只读七天投影，使用与每日 `plan_context` 完全相同的固定事件。全部课表视图也显示其他固定日程；指定课表仍将它与其他硬日程比较冲突。

`apply_timetable` 事务性保存容器与 `event` 系列，入口载荷包含 id/version（修改已有容器时）、title、semester_start（周一）、semester_end（含当日）、timezone、source_text、rows。每行 key/title/weekday（周一=0）/start/end，可加 owner_id（实际课程）、event_id/version、teaching_weeks（连续日历周整数列表）、enabled、location、event_kind、exceptions（日期到cancelled或start/end）。省略教学周表示已经确认每周，不能用来代表未知。更改已有时段必须带其版本；没有包含的旧行保持不动，停用须明确 enabled=false。单表100行、最长52周；不展开为整个学期每日实体。

资料范围为 `scope={kind:'timetable',entity_id}`。每轮重新读取容器、实际行和有限课程目录，资料引用经实际附件版本注入。该范围候选只允许 apply_timetable 当前容器；不能附带创建任务、课程、每日计划或改其他课表。外部 Codex 和 GUI 可直接调用同一命令，无需后台模型。

教学周与日期例外通过 timetable.occurs_on 同时约束 daily、warning、recurring preparation 三个路径。跨时区先筛选源本地教学周再投影业务日期，跨午夜可以分成两天；夏令时不存在/歧义的具体时刻保持unknown，不能当成确定空闲。学校非连续教学周需要有日期校历后明确换算，本版没有擅自推断校历的算法。

历史 0.6 实现（以下整份上限已由 0.14 分批机制替代）：课表 PDF 增加 source_worker layout_mode='timetable'，文字丰富页也渲染，最多8页/1600像素长边；超出页明确partial而非完整。普通资料保留原读取方式。课表渲染临时磁盘预留96MiB，仍受45秒/768MiB子进程限制和既有原件128MiB、附件12项、正文28000字符、图片8张上限。每张图按内容地址保存，重复导入复用。课表不复制文件到每个课程或每个星期。


## 0.7 教学周配置与任务删除

settings.timetable_defaults={week_numbering:'teaching'|'calendar',recess_weeks:[ISO Monday]}，默认teaching和空日期表；timezone复用系统settings.timezone。新导入将日期范围内的规则保存到容器与event，既有快照不被默认值变化覆盖。apply_timetable支持同名字段，改规则必须提交全部已有行及版本；旧无字段容器按calendar解释且相同重导入不增加版本。occurs_on统一过滤recess并在teaching模式扣除之前的假期周，再按teaching_weeks判断，源当地日期先算周再转换时区。

generic create timetable按同名称、起止范围复用当前未归档容器，并返回reused，不覆盖原规则快照；多匹配明确冲突。用户修改名称或范围可建立不同课表。导入两阶段回执不确定时保持原请求重试，不通过新容器规避幂等。

delete_task/restore_task载荷为{id,version}，复用archive审计和undo机制，无物理删除、无计划/反馈/链接级联。已删除实例不会被周期ledger重建，但未来正常新发生项仍能产生。每日复盘新增target_archived、can_review，summary.pending_review仅计可操作未反馈事项；原历史统计仍保留。已删任务禁止新反馈，恢复需重新校验父级/模块状态。

GUI只在设置课表页显示时读取配置，带epoch/revision和已读实体版本保存。Recess日期不明确时不推断，默认不计教学周并不等于已知道具体校历。暗色变为灰黑蓝色配色，主题偏好与字体配置字段保持兼容。


## 0.14 上下文扩展入口

新增业务集合通过 context_service.register_collection 注册名称、标签、实体类型、范围 SQL 条件及是否全局。条件必须使用参数绑定，注册来自受信软件代码，不接受模型生成的 SQL。模块自定义类型也可通过 records 和 read_context_item 读取，命令仍经现有类型注册及 Core 校验。

上下文、材料和候选状态属于独立操作表，不把解析进度写成用户业务事实，不因读操作增加业务 revision。数据库新增索引/触发器跟踪集合变化；实体版本与集合范围签名共同覆盖“已有项变化”和“新增成员”。source_context_operation 是业务记录对来源分析的引用，避免向每一条课程任务复制整门课的附件列表。

新解析器接入 material_worker.units，返回稳定自然单元位置、定位文字、text/image/gap 及内容；parse_batch 负责预算与继续位置。原件和提取块按哈希复用，checkpoint 只存候选事实和引用。新增提取逻辑须升级 EXTRACTOR，避免把旧缓存当作新版结果。

上下文生命周期由 context_driver 调度，单阶段预算覆盖双向工具内容、图像估算和调用次数。结束后的可重建分页缓存及仅索引读取记录会清理；事实、回执、来源版本、已处理批次及修订历史保留。普通无作业 MCP 操作超过两天后清除同类缓存。清理不会自动收缩 SQLite 文件，空闲页留给后续复用。
