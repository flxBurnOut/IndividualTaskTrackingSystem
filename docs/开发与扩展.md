# 开发与扩展

发布部分适用于个人事务管理 v1.2.0。包含按面板展示的新手引导、双客户端上下文、候选归属与长结果接口修复，以及保留数据的安装升级、运行版本核验、后台安全退出和 Windows 托盘。以下另外注明尚未发布的源码能力。

当前源码另有尚未发布的手动体验改造：`task_pool` 全局分页查询、任务快速记录、单日编辑草稿、手动依赖和课程内容编辑、无计划反馈、结构化习惯入口。`appearance.show_assistants` 只控制入口显示，不改变 AI 配置或已有作业；老设置未含该字段时继承原 `ai.enabled` 的显示意图。`assistant_activity` 仅查询待处理数量。

单日草稿由 `gui_plan_drafts` 存于当前数据目录的 `ui-plan-drafts`，按 epoch 和日期隔离，使用原子写入与比较令牌保护多窗口编辑。它不属于正式计划或业务写入，发布检查会拒绝把该目录混入安装包。新查询复用原有完成事实、版本和依赖校验；没有新增跨日计划事务或新助手提供方。

本轮源码增加 `task_batches` 与 `gui_task_batch`：批量创建及原任务拆分，先只读预览，再在一次 Core 事务中创建全部任务、来源关系、前置依赖和业务回执。不迁移数据库，不修改原任务、历史计划、反馈或累计进度。

## 开发环境与运行

需要 Python 3.12 或更高版本。依赖和可选开发工具以 `pyproject.toml` 为准。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m management --data-dir .local-data
```

`--service` 只启动业务服务，`--mcp` 提供 MCP 接口，`--choose-data` 只为本次启动选择数据空间。`--install-shortcuts --choose-data` 创建长期绑定所选数据目录的快捷方式；不会移动或导入原数据。开发和验收必须使用独立的合成数据目录，不把日常业务库作为测试夹具。

## 命令与状态语义

业务命令使用稳定 `request_id`、当前 `epoch/revision` 和必要实体版本。同编号同内容恢复原回执，同编号不同内容拒绝。不同请求编号不天然语义去重；复盘、托管资料、准备发生次等专用操作按各自规则去重。

长文件操作先登记意图，在业务事务外进行耗时 I/O，再结算结果与回执。未知结果应查询原操作；不得直接用新编号重放。恢复数据空间后更换数据身份，使旧上下文和候选失效。

进度与上下文读取缓存不是用户业务事实。它们记录材料定位、版本、检查点、处理代次和回执关联，不能把“已提取”“已交给模型”“已分析”“已采用”压成一个完成标志。

受管候选在一次业务事务中采用全部封存动作；失败整体回滚。直接 MCP 多命令是多个事务。现有计划修改走保护历史的专用入口，不能用新建计划绕过已有反馈。

## 扩展方式

1. **字段和视图**：声明式模块增加类型字段，字段版本受保护；停用后历史数据保留。
2. **规则**：支持声明式字段校验，以及有范围、效期的容量、保护时段和提前警戒。
3. **工作流**：调用已有受控操作并提供默认输入，使用正常类型化表单，不执行模块 JSON 内的任意代码。
4. **类型与算法**：新增命名空间类型，或注册 `CommandDefinition`、`QueryDefinition`，提供稳定名称、版本与自包含 schema。

算法注册来自受信应用代码。命令处理器参与同一事务，不在事务内运行模型或慢 I/O；有耗时任务时先登记持久作业，由受控执行器处理。新增复杂界面或外部能力仍需实现与验证，不是导入 JSON 就具备任意功能。

`capabilities` 返回当前类型、字段、流程和已注册扩展。MCP 按实时白名单调用。新类型可进入现有菜单和表单，但不会自动成为新的一级导航。

## 业务扩展边界

### 批量录入与任务拆分（尚未发布）

查询 `preview_task_batch` 接受 `mode=create|split`、`items`、明确布尔值 `sequential`，以及可选的 `parent_id/parent_version`（创建）或必填的 `source_id/source_version`（拆分）。每行仅接收 `title`、`completion_gate` 和可选的 `estimated_minutes`、`due_date`、`scheduled_date`。创建允许 1–50 项；拆分允许 2–50 项且每项完成标准必填。总关联最多 500 项，规范化输入不超过 180 KiB，超出时明确要求分批。

使用预览返回的 `command`、完整 `payload`（含 `preview_token`）、`epoch`、`revision` 执行 `create_task_batch` 或 `split_task`，并保持同一 `request_id`。内容、归属、源实体版本或数据修订变化后须重新预览；未知结果只能恢复或重试原请求。令牌是内容及版本校验，不是权限凭证。每个子任务使用原生 `parent_id`，同时记录指向原任务的 `contributes` 来源关联；全部子任务继承原前置，显式顺序仅添加相邻链。

批次审计 `task_batch` 阻止通用 `undo` 删除后来已被计划或反馈引用的任务。本期没有批量修改已有任务、整批撤销或跨日排程；用户可逐项使用正常编辑和删除入口。批量窗口保存未确认时锁定输入，避免改用新请求重复创建。

普通 MCP 的 `query_business` 与 `execute_command` 已登记这些能力；`preview_task_batch`、`task_pool`、`actual_feedback` 的长结果使用 `read_business_page` 保真续读。若预览原参数本身超出续读信封预算，明确返回 `business_page_budget`，不会截断后继续写入。受管讨论的候选白名单和权限没有扩展，不能从普通 MCP 可用推断受管候选也支持批量命令。

### 每日计划和复盘

`daily_tasks` 是日期相关待办投影；`add_to_plan` 需提供已读计划快照，追加任务时保留旧块，不自动改变休息模式。`revise_plan` 保留已反馈或过去条目。

`create_plan` 一次保存一个日期，最多100个块，检查时段、容量、任务完成条件和依赖。核心分钟数为整数。没有专门的多日区间事务 API；普通对话可逐日协调，一般候选可包含多个合法动作，但不能因此跳过逐日证据读取。

复盘的完成、出勤、提交、掌握和实际用时分别记录。固定课程按实际发生次反馈；只有明确缺课需补才建立补课关联，不能从未知出勤推断欠课。

### 准备和补欠

`recurring_rules` 与 `preview_recurring` 只读；`set_recurring_rule` 修改规则，`materialize_recurring` 显式生成有界日期窗口。规则和发生次账本防重复；修改节点与规则不覆盖已有任务和反馈。后台保存成功处理位置，有限追补遗漏日期，超范围需明确核对。

补欠复用任务与反馈，不建第二套进度事实。累计数量与完成确认独立，未知不转为0，降低数量需引用原记录并说明。已有完成条件不能在登记补欠时降低；范围或单位改变不能套用不相容的旧数量。

### 课表

课表容器保存名称与日期规则；实际系列使用共享日程实体。`timetable_week`、每日固定安排、警戒与准备生成共用日期和教学周判断。

`apply_timetable` 在事务内校验容器及实际行版本；未包含的旧行不自动删除。Recess 周必须有明确日期，旧规则保持原含义，不从空白周猜校历。

GUI 支持原系列同星期日期的单次停课或改时间；没有完整的单次跨星期迁移编辑器。周视图也暂不提供独立 Recess 周标题。新增此类界面不能只改变视觉而绕过共享日程语义。

## 长资料与候选

新增集合用 `context_service.register_collection` 注册，SQL 条件必须参数化并来自受信代码。记录细节通过有界读取器取得，索引和第一页不代表全量覆盖。

解析器按自然单元输出稳定位置、文本、图片或缺口，`parse_batch` 按预算保存继续位置。原件和提取块按内容哈希复用；改变解析语义应更新提取器版本，避免把旧缓存当作新结果。

当前机制没有旧的整份8页上限。长文档分批处理，但每批仍有资源预算，格式不支持或无法恢复的错误必须作为缺口返回。压缩与检查点接续沿原作业，不通过重置配额假造完成。

单批候选动作有界，累计候选用清单和分页读取。采用时校验整个清单。结束后的可重建缓存可以清理，事实、来源、回执和必要修订记录保留；清理缓存不承诺 SQLite 文件立即变小。

内置课程笔记流程通过有限技能注册表加载。本轮用户请求才选择技能，资料正文不能激活任意技能或路径。高级文档成果生成与采纳保留业务接口和执行器，但没有覆盖全部流程的独立 GUI，应在接入说明中明确。

## 桌面连接维护

正常桌面共享使用版本相关私有 IPC；必须验证服务器进程、路径和包身份，并以自己的客户端身份连接。不改 Codex 内部数据库，不伪造代理工具调用身份，不以隐藏模型替代共享模式。

发送意图先落盘，响应与历史按精确会话、回合和代次核对。断连后重新订阅，不能重发未知请求。正式取消与服务脱离不同；新代次进度只能由当前任务身份建立，旧回调不得回写。

官方 App Server 的配置、空会话创建和只读历史接口与私有桌面路由职责分开。接口 schema 中存在字段不代表当前运行时一定支持；适配应有协议、身份、重复、丢页、未知结果和恢复测试。

GUI 对象在所属线程释放，异步回调核对窗口生命周期、数据身份及请求代次；不得用后台线程直接更新或销毁 Qt 控件。

## 程序与数据升级

Windows 服务通过 `tray_runtime` 监督独立的 `PersonalManagement.exe --tray` 观察进程；每个数据空间通过 `tray.lock` 保证单实例。`gui_tray` 只读查询 `runtime_status`，禁用自动拉起服务；明确退出复用维护接口并标记 `reason=exit`。图标状态不等同于 Codex 连接状态。`tray-status.json` 是无凭据的临时显示诊断，不能作为业务事实或分发内容。

主窗口以 `gui.lock` 和限制当前用户的本地管道协调。管道仅接受显示、打开更新页和请求退出，业务读写仍走共享服务。退出请求先检查打开的编辑窗口、未提交复盘及未确认保存回执。`PERSONAL_MANAGEMENT_NO_TRAY=1` 仅用于隔离测试，避免后台测试创建大量系统图标。

界面、业务服务和 MCP 是独立进程。`state.service_contract` 包含发布版本、协议版本和必需能力；客户端先核验再接受连接，服务拒绝旧入口继续调用业务接口。`runtime_status` 单独记录最近一次入口请求的版本，不将动态诊断混入业务状态。新 MCP 探针成功不能证明其他已打开会话已刷新。

`maintenance/shutdown-if-idle` 是经过身份验证的维护入口，不是可供模型任意执行的业务命令。它拒绝正在执行的任务和写入，在持有数据锁的情况下设置更新暂停标记，等待后台结束后正常退出；读取批次耗时较长时也会自主完成退出，不依赖界面仍然打开。显式启动 GUI 将一次性恢复令牌交给选定的新服务；新服务取得数据锁并成功初始化后才移除暂停标记。

安装器沿用稳定 AppId 和原程序目录。规范数据路径来自已保存的安装设置，旧版首次升级可读取原快捷方式；路径缺失或冲突时停止，不能默认创建空库。已有资料目录与程序目录不能互相包含，安装和卸载不清空未知文件。旧便携版转安装版需选择原数据空间；不会自动删除未登记的便携目录。

`Store` 在修改旧数据库前创建经过核验的 SQLite 在线快照，涵盖已提交的 WAL 内容。全部启动迁移在同一事务中完成，与 `framework_version` 一起提交；失败回滚，失败后重试重新保存快照。快照是数据库快照，原始资料留在原目录；不得自动恢复旧数据库覆盖升级后的新增内容。早于 1.1.0 的程序不认识这些保护，首次升级须先退出其旧后台和旧 MCP。

## 构建和发布检查

日常修改复用对应 pytest 文件，新增检查补进 `tests/`，不要在 `.build` 中为每次验收重新生成脚本。指定测试入口必须选择文件或节点，避免小改动默认跑全量：

```powershell
.\.venv\Scripts\python.exe packaging/check.py focused tests/test_service.py
```

发布前按变更需要使用以下固定入口：

```powershell
.\.venv\Scripts\python.exe packaging/check.py full
.\.venv\Scripts\python.exe packaging/build.py
.\.venv\Scripts\python.exe packaging/check.py package
.\.venv\Scripts\python.exe packaging/check.py upgrade
.\.venv\Scripts\python.exe packaging/check.py tray
.\.venv\Scripts\python.exe packaging/check.py installer
.\.venv\Scripts\python.exe packaging/build_installer.py --bootstrap-compiler --check
.\.venv\Scripts\python.exe packaging/build_installer.py
```

`full` 将有 Qt 进程隔离要求的界面测试单独运行。`package`、`upgrade`、`tray` 使用既有冻结程序；缺少版本时直接提示，不重建用户删除的旧版。升级验收基线是保留的 1.0.2。`installer` 使用独立测试标识和合成资料，不替换用户安装。

结果固定存放在 `.build/checks/<类型>/`：`latest.json`、`latest.log` 和最新检查报告；失败另覆盖 `failure.json`、`failure.log`。日志最多保留末尾 2 MiB。每次运行的 `work/` 带归属标记，结束时回收测试进程并删除临时数据。确需调试才显式使用 `--keep-work`，也只保留一份。真实 `data/` 和升级备份不在清理范围。

来源、测试、依赖、解释器及相关冻结包的指纹相同且上次通过时，入口返回 `reused` 和原验证时间，不执行重复检查。它代表复用旧证据；环境或连接问题需要本次实测时加 `--force`。并行重复运行同一检查会被拒绝，防止日志和临时数据互相覆盖。

便携构建输出 `release/PersonalManagement-1.2.0/app/`，同一版本目录收纳安装 EXE、`.exe.sha256`、`SHA256SUMS.txt` 和 `manifest.json`。构建器保留已存在版本，不默认清空 PyInstaller 缓存。正在使用的历史版本可以保留原程序路径，解析器兼容其布局。首次执行 `--bootstrap-compiler` 会从官方来源取得固定编译器，核对哈希和签名后仅解包到 `.build/tools`。`--check` 校验输入并编译脚本，不生成安装包。不要把包含本机路径的测试报告作为发布附件。

`packaging/maintenance.py organize` 预览版本目录归并，`prune` 预览旧生成目录，整理目录用 `--apply` 执行；大批清理须在确认后用 `prune --plan 预览JSON路径 --apply` 绑定该清单。`prune --scope obsolete-releases` 只选 1.0 之前的发布目录。工具拒绝越界或被进程占用的路径，保留业务目录、升级备份、迁移记录和构建依赖缓存。历史一次性脚本仅作追溯，不作为标准入口。

源码提交并推送后，统一通过 `packaging/publish.py inspect` 核对版本和远端；`prepare` 创建草稿并上传安装包、校验文件，`publish` 在摘要和文件哈希核验后发布为最新版本，`verify` 回读发布结果。发布目录来自当前版本清单，仓库必须与 `origin` 一致；不覆盖其他提交已有的标签或不明来源的 Release。已有安装包和程序保持一致时直接复用，安装器的 `--check` 使用独立输出目录，避免触碰已发布文件。

这组安装器测试使用小型合成载荷验证安装规则，真实程序的业务迁移由冻结 EXE 验收单独证明。发布前还应核对最终完整载荷的安装结果，不能将不同产物或早期构建的报告当作最终包的验收。

应用构建会根据实际打包依赖生成 `THIRD_PARTY_NOTICES.md` 和许可证目录，并补充固定版本的官方 Qt 许可与来源说明。下载缓存位于 `.build`；缺失许可、版本不符或哈希异常时构建停止。安装器输入还会检查三个程序的版本、私有数据文件和前后哈希。

默认程序目录与数据目录分离。安装器遇到程序占用应提示处理，不强杀进程；普通卸载保留数据。当前没有代码签名证书，应在发布说明中如实标注，不能把校验和等同签名。
