# Beta 开发与验收

新开发会话先读 [开发交接与当前状态](开发交接与当前状态.md)，再按本页准备运行环境；原始路线与设计理由见 [手动优先与多助手接入方案](手动优先与多助手接入方案.md)。

`Beta` 是新增大功能的开发与验收分支；正式 Windows 版本继续在 `Windows` 分支维护。本目录是同一个 Git 仓库的独立、长期工作树，可以单独添加为 Codex 项目。它共用仓库历史和远程地址，但源码、构建目录和测试数据与正式工作目录分开。

## 当前状态

已在 v1.2.0 正式基线之上加入手动任务池、单日计划编辑与草稿、手动反馈与课程内容维护、可选助手入口，以及批量录入和任务拆分。源码中的数字版本仍为 1.2.0，用于保持本轮既有验证；本分支不代表新增的正式发行，也没有生成 Beta 安装包。

正式数据、数据库、资料附件、运行配置、旧安装包和本机验证报告不随分支迁入，也不提交远程。尚未实现跨日计划事务和新助手渠道。

## 后端和数据库隔离

2026-10-05 明确的开发约束：正式版需要持续日常使用，Beta 的后端服务和数据库必须完全独立，Beta 操作不得影响正式版运行。

- Beta 使用本工作树源码和自己的开发环境，启动独立后台进程；不复用正式版的服务进程或发布程序。
- Beta 数据库、附件、配置、日志、备份、服务锁及连接信息均保存在本目录的 `.beta-data` 下，默认空间为 `.beta-data/default`。备份恢复可选择 `.beta-data` 下另一个新目录，不得与正式空间重合，也不得通过目录链接指向正式空间。
- Beta GUI、MCP 和后台作业只连接 Beta 服务。同一环境内各入口共用业务服务、Core 规则和数据库；正式版与 Beta 之间不共用这些运行实例。
- 启动前核对程序来源和解析后的绝对数据目录，连接后核对服务返回的数据身份；身份不明或不一致时不接通。不得复制正式版的 `runtime.json`、认证令牌或锁文件来建立 Beta 连接。
- Beta 的退出、升级、测试回收和清理仅作用于已确认的 Beta 进程与目录，不停止或重启正式服务，不按进程名称批量终止，不修改正式安装登记、快捷方式或 MCP 配置。

2026-10-05 已加入源码保护：默认位置固定为本工作树的 `.beta-data/default`，忽略正式版数据环境变量和安装登记；显式目录也必须位于 `.beta-data` 下，或由统一检查入口创建并标记的 `.build/checks/<类型>/work` 内。数据库、服务连接、启动/退出恢复、资料恢复目标和 MCP 配置准备都校验目录，目录链接和共享数据库硬链接会被拒绝。连接握手增加 `beta` 通道，版本相同也不能接受缺少通道或通道不同的服务；后台同样拒绝不匹配入口的写入和退出请求。具体测试范围与结果见交接文档的验证记录。

## 添加到 Codex

把这个工作目录作为一个新的本地 Codex 项目添加，建议名称为“个人管理系统·Beta”。原正式目录继续作为正式项目。新会话开始时先确认工作目录、当前分支为 `Beta`，以及上游为 `origin/Beta`。

这是长期工作树。不要在文件管理器中单独移动或删除任一工作树的 Git 元数据；需要迁移目录时使用 Git 的工作树管理流程。

## 从源码运行

本目录使用独立 `.venv`，不借用正式版的运行环境。新检出目录首次运行时：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m management --data-dir .beta-data/default
```

也可双击本目录的 [启动个人事务管理Beta.vbs](../启动个人事务管理Beta.vbs)：它只使用本目录的 Python 环境和 `.beta-data/default`，缺少环境时明确报错，不寻找正式安装程序。窗口、托盘、版本页和独立入口统一标明“个人事务管理 · Beta 测试版”，Windows 应用身份独立。命令行省略 `--data-dir` 时同样使用该默认 Beta 空间；检查和自动化仍应明确传入要使用的目录。

`.beta-data` 受现有忽略规则保护。首次建立空空间，不复制正式资料或设置。需要用已有资料验收时，另按授权使用软件的完整备份与恢复流程建立副本，不让两版共享正在使用的数据库。恢复后先核对测试空间和助手设置，再明确启用需要测试的连接。Beta MCP 由本空间的配置准备功能生成，使用本目录的程序和 Beta 数据路径；正式 MCP 配置不能用于 Beta 验收。

## 专用演示数据库

Beta 开发默认使用虚构资料，不要求复刻正式版内容。2026-10-06 已通过业务接口在 `.beta-data/default` 建立配方版本 1 的演示空间，基准日期为 2026-10-06。示例任务、课程、项目和资料标有“【演示】”，计划与反馈保留虚构来源；收藏中的“先读这里：演示数据使用说明”给出浏览顺序。

| 功能 | 演示场景 |
| --- | --- |
| 项目与课程 | 两门虚构课程、项目/子项目/阶段、里程碑和目标；实验、运行记录和虚构数据集 |
| 任务池 | 135 个未删除任务，其中 120 个用于搜索与分页；另保留一个已删除任务用于恢复操作 |
| 任务语义 | 未估时/未定日期、逾期、部分完成、已完成但未提交、依赖受阻、拆分后的子任务链与清单 |
| 安排与反馈 | 昨天/今天/明天三份单日计划，明确反馈与周回顾；不伪造跨日原子计划能力 |
| 课程内容 | 评分组件、模拟成绩与未出分组件、知识点、错题与待复测、信息缺口、固定课表；补课总量 8 节、已推进 3 节 |
| 习惯与提醒 | 容量、保护休息、提前提醒和文字偏好；准备规则及复盘定时任务默认停用 |
| 资料与成果 | 一份虚构通知、三份原始示例文件及各自受管副本；由本地后台真实生成的一份 Markdown 成果 |
| 助手入口 | 展示入口但不配置账号、不调用模型；真实账户授权、外部助手派发和回传仍需单独验收 |

生成器位于 [demo_data.py](../src/management/demo_data.py)。它调用同一业务服务的命令、预览和回执，不直接写 SQLite，也不复制正式库。常用命令：

```powershell
# 首次生成；若此前已生成，则只回读，保留手工编辑。
.\.venv\Scripts\python.exe -m management --data-dir .beta-data/default --seed-demo

# 需要以新日期重新演示时，明确选择另一个新的 Beta 空间。
.\.venv\Scripts\python.exe -m management --data-dir .beta-data/showcase-next --seed-demo --demo-date 2026-10-07
.\.venv\Scripts\python.exe -m management --data-dir .beta-data/showcase-next
```

日期省略时采用首次生成当天（Asia/Shanghai），续跑固定使用原日期。更换基准日期或配方版本要使用新空间，不重写旧计划和反馈。无演示标记的非空库、已有设置、作业或待核对文件操作都会拒绝生成。

`beta-demo.json` 保存步骤、原请求号、完整预览和回执。意外中断可用原命令续跑；其他入口修改、数据 epoch 改变或导入结果需要核对时会停止，不能靠换请求号强行继续。生成不是跨全部步骤的单次原子事务，未完成状态会明确保留。完成后再次执行不会重置数据库或重新生成成果；要演示初始状态，选择新空间。数据、回执文件和 `demo-inputs` 均留在忽略目录，不提交。

## 提交与同步

- 数据库永远不提交或推送，正式库、演示库、测试库及其日志、备份和数据导出都留在本机；可以提交演示配方源码与测试。提交前同时检查已跟踪文件和暂存区，忽略规则不能代替这一步。
- 本目录提交到 `Beta`，跟踪同一远程仓库的 `origin/Beta`。
- 保持正常快进推送，不以强推覆盖他人提交。
- 验收通过后，再审查并把 Beta 的代码合并到 `Windows`；测试数据不会随代码合并。
- 测试继续复用 `AGENTS.md` 中的标准入口，测试产物留在本目录的 `.build/checks/`，由入口自动回收临时数据。

## 安装包与正式发行边界

现有安装器共用正式版安装身份，发布脚本使用正式最新版流程。当前 Beta 已阻止三个正式打包/安装包构建/发布入口执行，不生成或覆盖正式产物。Beta 也不改写正式安装登记。发布 Beta 安装包前，仍需实现独立安装身份、可分发的数据默认位置与预发布渠道，并通过对应验收；本轮只是源码运行隔离。
